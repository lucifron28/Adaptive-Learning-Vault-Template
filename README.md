# Adaptive Learning Vault — Software Engineering

An **AI-assisted, evidence-driven software engineering learning system** built with Markdown.

Study programming fundamentals, algorithms, software design, frontend, backend, databases, testing, security, systems, and delivery **without tying your learning to any single language or framework**.

> **Learning loop:** Diagnose → Learn → Attempt → Review → Correct → Apply → Recall → Record.

This repository is a **template for learning**, not a collection of completed lessons or a substitute for writing your own code.

## What makes this different?

- Adaptive diagnostics instead of forcing everyone through the same beginner sequence.
- One focused exercise at a time; the learner attempts before seeing the solution.
- Programming, engineering judgment, code review, debugging, and testing as complementary skills.
- Language-agnostic core concepts with stack-specific paths chosen by the learner.
- Evidence-based progress: *Recognized*, *Guided*, *Independent*, and *Retained*.
- Cumulative real-world projects that evolve as understanding improves.
- Spaced recall and honest records of mistakes and corrections.
- Versioned notes that survive AI chat sessions.

## Quick start

1. Use **Use this template** to create your own repository (public or private), or clone it.
2. Open `Learning System/START HERE.md`.
3. Copy `Learning System/Reusable Software Engineering Mentor.md` into a new AI chat. Tell the mentor your interests, previous experience, and goals.
4. Complete a short diagnostic. Create an adaptive course under `Courses/` using the templates.
5. Attempt each exercise yourself. Save evaluated lesson notes and track what is actually demonstrated.
6. Store application source in separate repositories when useful; link their reviewed commits in your project log.

**Obsidian is optional.** All notes are ordinary Markdown. **GitHub integration is optional.** If an AI cannot read or update your repository, copy your latest progress note into the chat and save the resulting notes yourself.

## Suggested learning areas

| Area | Examples — not a mandatory syllabus |
| --- | --- |
| Programming foundations | Variables, types, collections, functions, debugging, complexity |
| Problem solving | Data structures, algorithms, testing edge cases |
| Software design | OOP, interfaces, modularity, architecture tradeoffs, refactoring |
| Frontend | Browser model, HTML/CSS, JavaScript, TypeScript, UI frameworks |
| Backend & APIs | HTTP, API design, concurrency, authentication, reliability |
| Data & storage | SQL, modeling, constraints, indexes, transactions, caching |
| Quality & security | Tests, code review, threat modeling, secure development |
| Delivery & operations | Git, CI, observability, containers, deployment, performance |

Choose the sequence by **assessment evidence and goals**, not by checklist pressure. Languages and frameworks are examples of implementations, not prerequisites for the overall system.

## Rules

- A roadmap is a **plan**. A progress record contains **evaluated evidence**, not a fabricated success story.
- Self-reported execution, inspected source, and independently run tests are distinct evidence types.
- The learner owns their solutions. Mentors give small hints and explain code-review findings rather than silently implementing assignments.
- Use official language/runtime/framework documentation and specifications when claiming technical behavior.
- Never publish secrets, personal learning reflections, private project links, or other private information without review.
- No automatic sync or background work is implied by this Markdown template.

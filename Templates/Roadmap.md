# Roadmap — <Course>

> This is a **plan**, not evidence of completed lessons. Update it adaptively after assessments. **Connect relevant skills to meaningful project milestones**; not every concept needs a feature.

| Phase | Competencies | Exercise / evidence | Project milestone (if relevant) | Status |
| --- | --- | --- | --- | --- |
| 0 — Diagnostic + project choice | Current knowledge and real goal | Short evaluated assessment | Pick a small real problem and first useful behavior | Planned |
| 1 — Foundations | Fundamental mental models | Explanation and targeted drills | Implement a minimal working slice as soon as ready | Planned |
| 2 — Fluency | Tools, language/framework practices | Independent implementation and debugging | Extend the same artifact with one tested feature at a time | Planned |
| 3 — Applied engineering | Real use cases, testing, tradeoffs | End-to-end behavior checks and design reasoning | Integrate features and test real failure cases | Planned |
| 4 — Quality & delivery | Reliability, security, maintainability, shipping | Reviewed and verified evidence | Make the software usable, maintainable and shareable where appropriate | Planned |

Choose the project and stack with the learner. Describe a **small, observable deliverable** for the first milestone and avoid promising an entire app before essential prerequisites have been learned. See [Project-Based Learning](../Learning%20System/Project-Based%20Learning.md).

Define the actual subjects and order based on the learner's chosen field and diagnostics. Skip proven prerequisites and add further phases when justified.

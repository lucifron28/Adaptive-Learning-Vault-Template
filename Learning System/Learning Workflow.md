# Learning workflow

```text
Goal → Short diagnostic → Choose small real project + adaptive roadmap
  → Concept → Focused drill → Learner-owned project increment (when ready)
  → Review and verify → Record evidence + spaced recall → Extend project
```

## Principles

1. **Diagnose before teaching.** Don't waste time redoing skills already demonstrated.
2. **Use primary documentation.** Keep explanations version-aware where necessary.
3. **Implement rather than spectate.** AI provides criteria and small hints, not prewritten assignments.
4. **Practice toward a project.** Use focused drills to prepare real incremental features; avoid endless disconnected exercises. Not every concept requires a feature.
5. **Choose a small real problem and a runnable first slice.** The learner selects the project and stack after a short diagnostic.
6. **Work in vertical slices.** An executable, testable increment is better than a large scaffold.
7. **Review behavior and failure modes.** Include invalid inputs, boundary cases and regressions.
8. **Record uncertainty.** A roadmap is not evidence, and local reported tests are not reviewer-executed tests.
9. **Practice retrieval.** Revisit concepts later without notes.
10. **Preserve ownership.** Explicit consent is required for repository changes.

## Suggested session routine

Read the progress tracker → ask one spaced recall question if due → teach the next outstanding objective → learner attempts → review their evidence → correct/retest → update lesson note, progress and review queue.

See [Project-Based Learning](Project-Based%20Learning.md) for the exercise-to-feature ladder and milestone planning.

GitHub and Obsidian are optional. If connected tools are unavailable, provide copy-ready Markdown and request the next session's progress summary.
